# Optional feedback, Gemini services and final reports

Inspection → private inference → saved result → exports never requires engineer
feedback. A collapsed optional section records notes, condition corrections,
site measurements and method. Each save creates a separate revision in IndexedDB
schema4; original predictions are preserved. These anonymous operator reports
are unverified and training-ineligible. JSON/PDF/ZIP retain them separately.
No current model weights or production geometry implementation are replaced.

An explicit optional Gemini action interprets a saved review against its original
image. It reuses the private IAM gateway, Vertex model, signing secret and USD100
ledger. Results are image/review-hash bound, signed and create-only cached. Paid
requests are never automatically retried. Gemini proposes a canonical label and
boundary guidance, not measurements, calibration or engineering acceptance. No
review, no paid interpretation. This does not automatically fine-tune any model;
approved-example retrieval/training remains a separate future development stage.
Saving alone stores feedback on the current device; export it for backup. Explicit Gemini interpretation additionally retains the operator report and signed interpretation in private research storage, linked by original image/content hashes.

## Services and UX findings

Recent cloud logs show one422 inspection failure on21November. Request contents
were not retained there, so its precise input cannot be proven. Code inspection
found hidden3MiB/16MP limits, misleading15MB upload copy, and a gateway masking
input/auth/provider/budget failures behind the same message. Those boundaries
now have upfront checks and safe distinct messages. Large originals are not
silently resized or used to fabricate calibration. Compatible browsers without
createImageBitmap use a normal image decoder. Invalid images are rejected before
spending reservations. Corrupt image decoding maps to422 rather than503.

The upload suggestion deadline is aligned with the bounded worker/gateway
execution window instead of stopping at120s while server analysis can continue.
Reference lookup has a15s timeout. Missing physical references remain a calibration
requirement, distinct from Gemini reference suggestions and network failure.
Advisory responses are validated before caching rather than persisting invalid
Gemini output. Invalid responses cannot fabricate mm or verified calibration.

Final wording distinguishes pixel boundary evidence, calibrated research mm,
defect suggestions and acceptance. No candidates does not mean NORMAL/PASS.
Feedback is optional even when an engineering status remains REVIEW_REQUIRED.
PDF records now wrap and paginate without the former25-record truncation; a
calibrated result no longer receives a contradictory unavailable-mm sentence.

## Compare before replacing geometry

History identifies browser OpenCV from19May2026, Python seam code from18August
(abc6810), stricter seam safeguards from5November(3d696bf), rough boundary research
from7November(PR18/19), and independent local-normal recovery from14November
(PR49). No neural crack model has been established as the implementation meant
by that description; the rough/dark-boundary methods are OpenCV algorithms.

The comparison script evaluates identical original images, orientations and
full-frame areas. Historical code is executed using current dependencies, so
this is not an exact reproduction of its deployed runtime. On the available900mm
original: August code returned no pixel value, November seam code rejected,
rough profiling returned161.5px and local normals158.577px. This supports keeping
the current useful diagnostic path, but does not establish which version is
physically more accurate. The original150mm image is unavailable in the resumed
workspace; its annotated overlay is not substituted as original input. Previously
saved reports are preserved. No3–4mm value is forced by scaling or threshold tuning.

Reproduce with:

    python -m scripts.compare_historical_seams --case-root ORIGINALS --output comparison.json

Genuine physical scale and independent site/boundary references remain necessary
for accuracy comparisons. Camera resolution and DPI alone are not calibration.

Phone EXIF orientation is applied consistently to research decoding so displayed
photos, segmentation and geometry share the oriented-original coordinate system.
Original bytes/hashes are unchanged. Existing calibration still must match the
resulting dimensions and image geometry; a rotated image is not an implicit
calibration transfer.
